# Page Anatomy — Standard Institutional Pages

Reference for what each standard page of an institutional site should contain. For each page: purpose, audience, sections, anti-patterns, and references.

---

## 1. Home Page

### Purpose
The home page is a **router**, not a destination. It answers "what is this?" and sends each audience down their path in under 5 seconds.

### Primary audience
Everyone — but the hero speaks to the primary audience, not all.

### Sections (standard order)

1. **Hero**
   - Headline (what you do + for whom)
   - Subheadline (how or why)
   - Primary CTA (+ optional secondary)
   - Supporting visual (product shot, editorial image, video)
   - Trust line under CTA if applicable

2. **Social proof bar** — client/press/investor logos, or a "trusted by X teams" line

3. **Value / services overview** (3-5 blocks)
   - Short name, 1-line description, link to deeper page
   - Shows the breadth of what you do without overwhelming

4. **Featured case / proof** — one or two highlighted cases with real numbers

5. **Differentiator block** — why you, in a way no competitor could claim

6. **Thought leadership teaser** — latest blog posts or insights

7. **Press / awards bar** — optional, if relevant

8. **Final CTA band** — contact, book a call, learn more

9. **Footer** — secondary nav

### Anti-patterns
- Hero that doesn't say what you do
- Mission statement as headline
- Multiple competing primary CTAs
- Autoplaying video with sound
- Cramming the whole story on one page (that's what the rest of the site is for)
- Generic stock photos
- Scrolling carousels (users rarely click past slide 1)

### Home page length
- Short org (boutique, solo) → 5-6 sections
- Medium org → 6-8 sections
- Large org with many audiences → 8-10 sections + anchor links

## 2. About Page

### Purpose
Build credibility, establish mission, humanize the organization, explain the founding WHY.

### Audience
Prospective customers, investors, talent, press — anyone deciding whether to trust you.

### Sections

1. **Lead paragraph — the WHY**
   - Start with the problem you saw, not the year you were founded
   - Pattern: *"We started [Company] because [frustration]. We believe [conviction]."*

2. **The story** (optional for young orgs, essential for mature ones)
   - Chronological narrative with key moments
   - Specific — real dates, real decisions, real pivots
   - Not a timeline graphic if the story is richer than dates

3. **Mission + values**
   - Short, specific, lived
   - Each value with 1 line of "what this means in practice"
   - Not posters — actual operating principles

4. **What we do** (short — details live on /services)
   - 2-3 sentences
   - Links to Services / Products / Work page

5. **Team highlight** — founders or exec team (link to full /team page if you have one)

6. **Numbers** — years, clients, countries, projects — whatever's true and impressive

7. **Credentials** — awards, press, certifications, investors, notable partnerships

8. **CTA** — Contact / Careers / Work with us

### Anti-patterns
- "Founded in 2015, Acme is a..." — boring opener
- Mission statement as the hero ("To empower...")
- Generic values ("Integrity, Excellence, Innovation")
- Stock team photos
- No story, just a timeline
- Corporate boilerplate copied from the press kit
- Missing founder / leadership info (looks fake)

## 3. Services / What We Do

### Purpose
Explain what you actually sell/do in concrete terms. Map offerings to buyer needs.

### Audience
Prospective customers in research mode.

### Sections

1. **Hero** — clarifying what this page covers
2. **Services overview** — grid or list of offerings
3. **Per-service detail** — for each:
   - Name (plain, not jargon)
   - 1-line description
   - Who it's for
   - What's included / deliverables
   - Process or timeline
   - Proof (one metric, one quote, or a link to a case)
   - CTA (learn more, get started, talk to us)
4. **Methodology / how we work** — optional, for services firms
5. **FAQ** — top 3-5 objections
6. **CTA band**

### Variants by org type

- **B2B SaaS**: Products (named) with features → benefits mapping
- **Agency**: Services (design, dev, strategy) with case links
- **Consultancy**: Practice areas with senior advisor bios per area
- **Law firm**: Practice areas with partner profiles
- **Clinic**: Treatments with conditions they address

### Anti-patterns
- Generic service names ("Strategy" — strategy for what?)
- Features without benefits
- No pricing indication (even "starting at" or "custom") — hurts qualification
- Nothing tangible (deliverables, process, timeline)
- No proof per service

## 4. Cases / Work / Portfolio

### Purpose
Prove you can do what you say. Show, don't tell.

### Audience
Prospective customers in evaluation mode, validating your claims.

### Index page sections

1. **Hero** — brief intro to what's below
2. **Filter / category nav** — by industry, service type, year, size
3. **Grid of cases** — thumbnail + client name + short headline
4. **Pagination or "load more"** — if > 20 cases

### Case study page sections (classic Challenge / Approach / Outcome)

1. **Hero**
   - Client name + logo
   - Headline: outcome in one line (*"How Acme cut checkout time by 60%"*)
   - Meta: industry, services used, timeline, team size

2. **The challenge** — what problem the client faced (specific, with numbers if possible)

3. **The approach** — what you did (high level — no trade secrets)

4. **The outcome** — results, with numbers and a client quote

5. **Process artifacts** (optional) — wireframes, screenshots, code snippets, before/after

6. **Credits** — who worked on it

7. **Related cases** — 2-3 similar cases for deeper exploration

8. **CTA** — "Work with us on something similar"

### Anti-patterns
- Vague outcomes ("improved efficiency")
- No client logo (looks fake)
- No numbers
- Hidden behind a form wall
- Generic stock shots instead of real work
- Too much text, no visual
- No client quote (or worse — anonymous quote)

## 5. Team / People

### Purpose
Humanize the organization, showcase credentials, build individual trust.

### Audience
Prospective customers (for services firms where relationships matter), candidates evaluating culture, press.

### Sections

1. **Hero** — short intro to the team
2. **Leadership / founders** — highlighted separately
3. **Full team grid**
   - Photo (consistent style — all headshots or all candid)
   - Name
   - Role
   - 1-line bio with specific credential + human detail
   - Optional: link to LinkedIn, personal site

4. **Optional groupings** — by department, by office, alphabetical

### Anti-patterns
- Stock photos
- Inconsistent photo styles (half smiling, half moody, half at desks)
- Vague roles ("Ninja Engineer", "Customer Success Enthusiast")
- 100 faces with no hierarchy
- Missing founders
- No way to contact individuals (if that's part of the value)
- Every bio starting with "Passionate about..."

### Team section on small sites
If you have < 10 people, the team can be a section on /about rather than its own page.

## 6. Careers

### Purpose
Recruit talent. Show why working here is meaningful.

### Audience
Candidates deciding whether to apply.

### Sections

1. **Hero** — why work here (mission + aspiration)
2. **How we work** — remote / hybrid / in-person, async, rituals, tools, working hours
3. **Benefits** — honest and specific (not "competitive salary")
4. **Culture proof** — photos, testimonials from current team, press, awards (Great Place to Work, etc.)
5. **Interview process** — steps and what to expect
6. **Open roles** — list with filters (location, type, department)
7. **No open role?** — "Send us your resume" option
8. **FAQ** — remote policy, visas, diversity, etc.

### Per-role page sections

1. **Role title + location + type + compensation range** (yes, publish it)
2. **About the role** — what you'll do
3. **About you** — requirements and nice-to-haves
4. **About the team** — who you'll work with
5. **How we interview** — process, timeline
6. **How to apply**
7. **Optional**: "What we don't care about" (degree, years, specific tools) — powerful for modern candidates

### Anti-patterns
- Just a link to Greenhouse / Lever with no context
- No compensation range (in 2026 this is a red flag for candidates)
- "Rockstar ninja wanted"
- Vague benefits ("great culture")
- No interview process transparency
- Missing remote policy
- No team pictures or day-in-the-life content
- "Fast-paced environment" (codes for burnout)

## 7. Contact

### Purpose
Let people reach you, with minimum friction.

### Audience
Everyone — customers, press, candidates, partners, random inquiries.

### Sections

1. **Hero** — simple, welcoming
2. **Direct contact methods**
   - General email (written, not behind a form)
   - Phone (if relevant)
   - Physical address (if relevant)
   - Office hours
3. **Contact form** — short
   - Name, email, message
   - Optional: category dropdown (Sales / Support / Press / Careers / Other)
   - NEVER: phone required, company size, "how did you hear about us"
4. **Response time expectation** — "We respond within 1 business day"
5. **Specific contacts for specific audiences**
   - Press: press@example.com
   - Support: help@example.com
   - Careers: careers@example.com
6. **Map** — if physical office matters (for retail, clinics, firms)
7. **FAQ** — if you get the same questions repeatedly

### Anti-patterns
- Form with 10+ fields
- No direct email address (forces the form)
- Phone number as "required"
- No response time expectation
- Form + email but they don't agree on what to use
- Contact page requiring login
- Success message that doesn't tell you what happens next
- Contact info only in footer (give the visitor a dedicated page)

## 8. Press / Media

### Purpose
Make journalists' jobs easy. Give them everything they need to write about you without asking.

### Audience
Journalists, PR partners, analysts, investors.

### Sections

1. **Boilerplate** — the paragraph you want press to copy-paste (one paragraph, about the org)
2. **Quick facts** — founding date, founders, employees, funding, customers, locations
3. **Recent news** — press releases and company announcements
4. **Press coverage** — links to articles, podcasts, features
5. **Founder / exec bios** — with photos
6. **Brand assets** — logos (PNG, SVG), brand colors, photos, usage guidelines
7. **Press contact** — direct email to a real human
8. **Awards** — list

### Anti-patterns
- No boilerplate (you force journalists to write your description)
- No downloadable assets
- No press contact
- Quick facts missing or outdated
- Dead links to old articles
- Investor info missing (if public)

---

## 9. Blog / Insights / Journal

### Purpose
Build authority through thought leadership, drive SEO, nurture audiences over time.

### Audience
Existing and prospective customers doing research, industry peers, SEO organic traffic.

### Index page sections

1. **Hero** — intro to the publication (what topics, who it's for)
2. **Featured post** — curated top-of-page
3. **Recent posts grid** — thumbnail + title + excerpt + author + date + read time
4. **Categories / tags** — if > 20 posts
5. **Pagination or infinite load**
6. **Newsletter signup** — if you have one

### Post page sections

1. **Hero** — title, subtitle, author, date, category, read time
2. **Cover image** — optional
3. **Body** — the content (1500-2500 words typical for in-depth posts)
4. **Author bio** — at bottom
5. **Related posts** — 2-3 similar
6. **Comments** — optional, rarely worth it for institutional sites
7. **Share buttons** — minimal, 2-3 max

### Anti-patterns
- No categories, no filtering (discovery impossible)
- Posts without dates (trust killer)
- Author bio missing
- "Click to continue" pagination mid-article
- Popup subscribe modals on scroll
- Giant hero images on every post
- Stale posts at the top (shows lack of cadence)
- No RSS feed (still useful in 2026)

## 10. Legal Pages (Privacy / Terms / Cookies / Accessibility)

### Purpose
Comply with regulations AND communicate honestly with users.

### Audience
Users (for privacy/terms), regulators, lawyers, candidates doing due diligence.

### Sections (privacy policy example)

1. **Effective date + version history link**
2. **Table of contents** — sections hyperlinked
3. **What data we collect** — specific, not generic
4. **How we use it**
5. **Who we share with** — vendors named
6. **How long we keep it**
7. **Your rights** — GDPR / CCPA / local
8. **How to contact us**
9. **Changes to this policy**

### Rules

- **Plain language first, legal language second**
- **Table of contents** — visitors should find specific clauses fast
- **Prominent "last updated" date**
- **Version history** link
- **Contact info** for privacy questions (`privacy@` or similar)
- **Accessible format** — no PDFs, no scans, no images of text

### Good references
- Basecamp's policies (famously plain)
- GDPR.eu templates (legally sound)
- Termly / Iubenda if you need generators — but review output

### Anti-patterns
- Walls of text with no headings
- Legalese you don't understand (how will users?)
- Missing "last updated" date
- No way to contact about privacy
- Scanned PDFs
- Copy-pasted from a template without customization
- Different policies on different subdomains

## 11. Investor Relations (for public companies)

### Purpose
Transparency with shareholders and prospective investors, regulatory compliance.

### Audience
Investors, analysts, regulators.

### Sections

1. **Stock quote / ticker** — real-time if public
2. **Financial reports** — annual, quarterly, archived
3. **SEC filings** (US-listed) — 10-K, 10-Q, 8-K
4. **Press releases** — financial-focused
5. **Events** — earnings calls, annual meetings
6. **Corporate governance** — board, committees, policies
7. **Presentations** — analyst decks, investor day recordings
8. **Contact** — investor relations direct email

### Rules
- **Legal review required** — everything here is regulated communication
- **Clear archive** — old reports never deleted, only archived
- **Audio/transcript** — earnings calls in both formats
- **Disclaimer language** — forward-looking statements legal boilerplate

---

## 12. 404 / Error Pages

### Purpose
Soft landing when something went wrong. Don't lose the visitor.

### Audience
Users who hit a broken link or typo'd URL.

### Sections

1. **Clear headline** — "Page not found" (not clever to the point of confusing)
2. **Short friendly message** — acknowledge the issue
3. **Helpful options**:
   - Search bar
   - Link to home
   - Links to popular pages
4. **Light personality** — okay to show some brand warmth here
5. **Contact** — "if you think this is a bug, let us know"

### Anti-patterns
- Plain white "404"
- Over-the-top humor that doesn't match brand
- No way to navigate away
- Auto-redirect without telling the user

---

## 13. Search Results Page (if you have search)

### Purpose
Help users find what they were looking for when browsing didn't work.

### Sections

1. **Search bar** (with current query)
2. **Results count**
3. **Results list** — title, excerpt, category, link
4. **No-results state** — alternatives, contact, popular pages
5. **Optional**: filters (by section, by date, by type)

---

## 14. Changelog / Updates / News

### Purpose
Show momentum, build trust, communicate changes to existing users.

### Sections

1. **Reverse-chronological list** of updates
2. **Date + version + title** per entry
3. **Short description** — what changed, why, how it affects users
4. **Category tags** — new feature / improvement / fix / security

### Anti-patterns
- Irregular updates (looks abandoned)
- Too technical for the audience
- No dates (can't tell if this is recent)
- Overly marketing-y (changelogs should be factual)

Good examples: Linear, Stripe, Vercel, Notion.

---

## 15. Resources / Guides / Docs

### Purpose
Long-form content that educates and serves as lead magnet.

### Sections

1. **Topic index** (often tab-based: Guides, Templates, Reports, Webinars)
2. **Featured resource**
3. **Grid of resources** — cover image + title + type + length + CTA
4. **Gated vs ungated decision** — if gated, require only email
5. **Search / filter** for larger libraries

---

## 16. Partner / Integration Pages

### Purpose
Show ecosystem, signal maturity, support partner channels.

### Sections

1. **Hero** — what kinds of partners
2. **Partner directory** — searchable/filterable
3. **Per-partner page** — logo, description, link out, join-CTA if mutual
4. **Become a partner** — CTA for new prospects

---

## Page Anatomy Checklist

For any page you design, verify:

- [ ] Clear single purpose
- [ ] Defined primary audience
- [ ] Hero answers "what / who / why" in 5 seconds
- [ ] Nav visible and functional
- [ ] Primary CTA present
- [ ] Mobile layout defined
- [ ] No vendehumo / no corporate-speak
- [ ] Proof present where credibility is needed
- [ ] Contact path accessible
- [ ] Meta title + description written
- [ ] Accessibility addressed
- [ ] Load performance under 2s
- [ ] Legal links reachable
